# 黑暗武士/缔造者「自我觉醒」服务端支持 — 问题分析与实现建议

> 2026-09-10 排查报告。
> 现象来源：GM 工具将黑暗武士角色改满级并跳过任务后，游戏内无法自我觉醒；
> 游戏内觉醒任务券（FirstAwakenClear）对黑武反复使用无效。
> 本文档给出根因定位、PVF 数据实证、服务端缺口清单与修改建议，供服务端开发实施。

---

## 1. 结论摘要（TL;DR）

1. **觉醒写入链路服务端已经完整实现**：任务奖励 `[reward type] [awakening type]` → `QuestRewardDefinition`（chainType=2）→ `QuestCompletionApplicationService.UpdateGrowType(chainType:2)` 只写 `grow_type` 高 4 位、保留低 4 位——这正是无转职职业（黑武/缔造者）自我觉醒的正确数据形态。**不需要新写任何"应用觉醒"的代码。**
2. 缺口只在**任务接取侧**，共三处：
   - 自觉任务 grade 为 `[realization]`，不在 `QuestRelationIndex.IsSelectableGrade` 白名单 → 任务永远不可接；
   - `MeetsCharacterRestrictions` 对 `jcq==2/3` 要求 `firstGrow > 0`（已转职），黑武/缔造者 first 恒为 0 → 二觉任务 2681（jcq=3）即使白名单放行也接不了；
   - 觉醒任务券 `FirstAwakenClear` 按 `JobChangeQuestValue == 2` 匹配目标，而一觉任务 2680 **没有** `[job change quest]` 标签（觉醒走奖励字段）→ 券匹配不到。
3. PVF 数据实证（`Script.pvf`）：
   - 黑武觉醒**无可见的名字/属性/送技变化**（觉醒名两档都叫"黑暗武士"；觉醒属性表与基础表数值相同；.chr 无 `[awakening skill]`）；
   - 觉醒的实际效果 = `skill/DSSwordmanSkill.lst` 中 250-257 号技能（幽魂剑/斩龙破/暗炎冥魂波/邪影升龙斩/超时空碎裂/次元融合/时间停滞）在觉醒位写入后变为可 SP 学习（`[second growtype maximum level]` 12 槽表，growType=0 占第 0/1 槽，上限 30）。

## 3. 机制分析

### 3.1 grow_type 编码（一字节两半字节）

```
grow_type: 低 4 位 = 转职 (first, 0-5)，高 4 位 = 觉醒 (second, 0-2)
黑武/缔造者无转职子职业 → first 恒为 0
自我觉醒 = first 保持 0，写 second (1=一觉, 2=二觉) → 0x10 / 0x20
```

服务端权威写入函数 `QuestCompletionApplicationService.UpdateGrowType`（`Game/Quests/QuestCompletionApplicationService.cs:1539-1663`）：

```csharp
var firstGrow = currentGrowType & 0xF;
var secondGrow = (currentGrowType >> 4) & 0xF;
if (chainType == 1) firstGrow = growNumber;
else if (chainType == 2) secondGrow = growNumber;   // ← 只写高 4 位, 保留低 4 位
var newGrowType = (byte)((secondGrow << 4) | (firstGrow & 0xF));
```

**该函数对 first=0 完全合法**——服务端数据层从一开始就支持无转职觉醒。

### 3.2 黑武职业数据（`character/Swordman/DSSwordman.chr`）

实证解包结果（全文 12922 字符）：

```
[job] `[demonic swordman]`
[growtype name] `黑暗武士` ×6            ← 基础名+5 个占位转职名, 全部同名
[initial value] … [skill]…[/skill] …    ← 唯一一个 [skill] 块(初始技能)
[growtype 1]
    [CHARACTER ATTACK TYPE] [physic]
    基础属性成长表
    [awakening name]
    `黑暗武士` `黑暗武士`                ← 一觉/二觉名, 与未觉醒同名
    [awakening 1] 属性成长表             ← 数值与基础表相同
    [awakening 2] 属性成长表             ← 数值与基础表相同
[waiting motion] …(动画段)
```

要点：

- **没有** `[awakening skill]`，没有任何自动赠送的觉醒技能；
- 觉醒属性表与基础表数值相同（GM 工具覆写觉醒后 HP 49850 前后完全一致的原因）；
- 因此觉醒后的可见变化**只有**觉醒技能变为可学习（见 3.3）。

属性重算链路（`Game/Characters/CharacterStatComputer.cs`）：`GetGrowth(first=0, second>0)` 读 `Awakening[1, second]`，即 `[growtype 1]` 段内的觉醒表——黑武数据存在，链路畅通。

注意：**2680 没有 `[job change quest]` 标签**（jcq=0），觉醒完全通过奖励字段 `[awakening type]` 应用。

两个任务的目标职业都同时包含 `[demonic swordman]`（黑武）和 `[creator mage]`（缔造者）——**同一修复同时开启两个职业的自觉**。

## 4. 服务端缺口定位

### 缺口 A（主因）：`IsSelectableGrade` 白名单缺 `[realization]`

`GameWorld/QuestRelationIndex.cs:431-444`：

```csharp
private static bool IsSelectableGrade(string grade)
    => grade == string.Empty
        || grade == "[normal]"
        || grade == "[side]"
        || ... // [sub]/[epic]/[training]/[achievement]/[daily]/[daily random]/
               // [normaly repeat]/[special daily]/[common unique]/[system]
```

→ `[realization]` 不在名单，`ComputeAcceptableQuests`（同文件 :69-146）在 :115-116 直接过滤，2680/2681 **永远不可接**。全服源码中 `realization` 零命中（除 PVF 数据外无任何处理），即该 grade 从未实现。

### 缺口 B：`jcq==2/3` 接取门要求 `firstGrow > 0`

`QuestRelationIndex.cs:208-226`：

```csharp
if (jobChangeQuest == 2)
{
    // First awakening is available only after transfer ...
    if (firstGrow <= 0 || secondGrow != 0)      // ← 黑武 firstGrow 恒 0, 永远 false
        return false;
    if (quest.GrowType != -1 && quest.GrowType != firstGrow) return false;
}
else if (jobChangeQuest == 3)
{
    if (firstGrow <= 0 || secondGrow != 1)      // ← 同样挡死黑武二觉
        return false;
    ...
}
```

- 2680 无 jcq 标签，只被缺口 A 挡（其 `[grow type]` 缺省 -1，不参与 grow 比对）；
- 2681 带 jcq=3，即使修了 A 仍被 B 挡。

### 缺口 C（券）：`FirstAwakenClear` 匹配不到 2680

`Game/Quests/QuestCompletionTicketService.cs:786-807`：

```csharp
case QuestCompletionTicketActionKind.FirstAwakenClear:
    return quest.JobChangeQuestValue == 2;      // 2680 的 jcq=0 → 匹配不到
case QuestCompletionTicketActionKind.SecondAwakenClear:
    return quest.JobChangeQuestValue == 3;      // 2681 jcq=3, 修完 A/B 后券可匹配
```

券的目标查找（`TryFindNextDynamicQuest`，:719-754）只扫 acceptable/active 集合。**二觉券在 A+B 修复后即对 2681 生效；一觉券还需要 C 的匹配条件放宽。**

## 5. 修改建议

按优先级（最小改动优先）：

### 5.1 【必改·P0】白名单放行 realization grade

`QuestRelationIndex.cs` `IsSelectableGrade` 增加：

```csharp
|| grade == "[realization]"
```

效果：2680（无 jcq、等级 50-99、前置 4484 已完成、目标职业匹配）立即进入可接列表；接受后见 NPC 127 完成即触发 `[awakening type] 1` 奖励链 → `secondGrow=1`。**只改这一行，黑武一觉的正规游戏内流程即完整可用。**

### 5.2 【必改·P0】jcq==2/3 接取门对无转职职业放行 first=0

`QuestRelationIndex.cs` `MeetsCharacterRestrictions`。建议引入"无转职职业"判定（黑武=9、缔造者=10；或数据驱动：该职业 `.chr` 的 `[growtype name]` 转职名数量为 0）：

```csharp
var hasNoSubclass = characterJob == 9 || characterJob == 10;   // 黑暗武士 / 缔造者

if (jobChangeQuest == 2)
{
    if (firstGrow <= 0 && !hasNoSubclass) return false;
    if (secondGrow != 0) return false;
    if (quest.GrowType != -1 && quest.GrowType != firstGrow) return false;
}
else if (jobChangeQuest == 3)
{
    if (firstGrow <= 0 && !hasNoSubclass) return false;
    if (secondGrow != 1) return false;
    if (quest.GrowType != -1 && quest.GrowType != firstGrow) return false;
}
```

注意：对无转职职业，`quest.GrowType` 的比对（2680/2681 均未定义该标签，缺省 -1）不受影响；若未来 realization 任务定义了 `[grow type] 0` 也能匹配 first=0。

效果：2681（二觉）对已一觉（secondGrow==1）的黑武可接，完成 → `secondGrow=2`。

### 5.3 【建议·P1】一觉券匹配条件放宽

`QuestCompletionTicketService.MatchesDynamicTarget` 的 `FirstAwakenClear` 分支建议同时接受"觉醒奖励型"任务：

```csharp
case QuestCompletionTicketActionKind.FirstAwakenClear:
    return quest.JobChangeQuestValue == 2
        || 奖励包含 QuestRewardKind.AwakeningType 且参数为 1;   // 2680 走这里
```

（`SecondAwakenClear` 已能通过 jcq==3 匹配 2681，无需改。）

### 5.4 【无需改】的相关链路（验证即可）

- 觉醒应用链 `UpdateGrowType(chainType:2)`：已支持 first=0（3.5）；
- 学技门 `BuySkillService → GetMaxLevelFor`：无 first>0 限制（3.3）；
- 技能快照 `CharacterSkillProfile.GetGrowTypeGrants` 的 `growType > 0` 门：只影响"觉醒技自动赠送"，黑武 .chr 本就没有 `[awakening skill]` 数据，该门对本案例无影响（保持现状即可，与服务端原版语义一致）；
- 客户端同步：角色列表/用户信息包已直发 grow_type 字节（3.6）。

## 6. 回归风险与注意点

1. **普通职业不受影响**：5.1 只放行新 grade；5.2 的放行条件含 `hasNoSubclass`，普通职业（first 必须来自转职）行为不变。建议跑 `GrowupChangeSelfTest`、`A21TutorialProtocolSelfTest` 回归。
2. **任务完成类型 `[meet npc]`**：2680/2681 的完成触发是"见 NPC 127"。若该类型触发未覆盖 realization grade 的任务，完成侧需一并验证（`QuestCompletionApplicationService` 的完成判定/`[condition]` 处理）。
3. **缔造者（job 10）连带生效**：2680/2681 的 target character 同时含 `[creator mage]`。缔造者技能表（`CreatorMageSkill.lst`）是否也有 second-growtype 觉醒技能、其 .chr 是否有 `[awakening]` 数据，请一并确认（若没有，任务照常完成、写 second 位，仅无技能收益）。
4. **等级窗口**：2680 是 50-99、2681 是 75-99，满级角色在窗口内，无问题。
5. **跳任务用户的前置**：本例 4484/4488 已在完成表中；若前置被跳过未标记完成，任务不可接——属正常门控，可由 GM 工具补标完成。
6. **客户端显示**：黑武觉醒名与未觉醒同名（`黑暗武士`），觉醒后客户端**不会有名字/属性面板的可见变化**，验证应以"觉醒技能可学"为准（技能 250-257）。

## 7. 验证清单（服务端改完后）

1. 未觉醒黑武（grow=0x00，等级≥50）登录：服务端日志 `[QuestRelationIndex] acceptable=N` 数量增加 1（2680 进入可接列表）；
2. 游戏内接取并完成 2680（见 NPC 127）→ `SELECT hex(grow_type) FROM characters WHERE character_id=<cid>` 应为 `10`；技能窗口 250-257 可用 SP 学习；
3. 一觉后 2681 可接（需 5.2）→ 完成 → `grow_type` 应为 `20`；二觉技能（次元融合/时间停滞，上限 1）可学；
4. 觉醒任务券：一觉券（需 5.3）与二觉券（5.1+5.2 后即应生效）对黑武不再报 `NoEligibleQuest`；
5. 回归：普通职业（如剑魂→剑圣）的觉醒任务接取、完成、觉醒券流程不变；`GrowupChangeSelfTest` 等自测通过。
